# Personal Links technical demo script

## Demo goal

Show two reusable Microsoft 365 development patterns:

1. One shared React and Fluent UI experience can run in a SharePoint web part, a SharePoint full-page
   app, a Microsoft 365 Copilot inline component, a Copilot full-screen component, and a Teams personal
   app.
2. OneDrive App Folder storage can keep per-user component state consistent across those hosts and
   devices while requesting only `Files.ReadWrite.AppFolder`.

Recommended duration: 15-20 minutes.

## Presenter checklist

Complete these checks before the session:

- Use a tenant where the SPFx 1.24 Copilot Component preview is enabled.
- Confirm the presenting account has a provisioned OneDrive.
- Deploy `sharepoint/solution/personal-links.sppkg` to the tenant App Catalog.
- Approve Microsoft Graph `Files.ReadWrite.AppFolder` under
  **SharePoint admin center > Advanced > API access**.
- Add the Personal Links web part to a SharePoint page.
- Make the same web part available as a SharePoint full-page app if that surface will be demonstrated.
- Install the generated Copilot agent package from `teams/personal-links.zip` through the custom
  app/agent installation flow supported by the demonstration tenant.
- To demonstrate Teams, upload `teams-app/personalLinks/TeamsSPFxApp.zip` as a custom Teams app after
  deploying the SPPKG.
- Confirm custom app upload is permitted by the tenant's Teams and Microsoft 365 policies.
- Seed three to six links with recognizable titles, different icons, and safe demonstration URLs.
- Open the SharePoint page and Copilot before presenting so authentication and OneDrive provisioning
  do not consume demo time.

Keep the two ZIP files distinct:

| Artifact | Install location | Purpose |
| --- | --- | --- |
| `sharepoint/solution/personal-links.sppkg` | SharePoint tenant App Catalog | Deploys the shared SPFx implementation, web part, Copilot component, and Graph permission request |
| `teams/personal-links.zip` | Supported Microsoft 365 Copilot/custom app installation flow | Installs the Personal Links declarative agent |
| `teams-app/personalLinks/TeamsSPFxApp.zip` | Teams custom app upload or organization app catalog | Adds a Teams personal-app shell that routes to the deployed web part |

The Copilot ZIP is generated by the SPFx build and is also packaged in the SPPKG. The handcrafted Teams
personal-app ZIP is intentionally outside SPFx's reserved `teams` folder, so it is never mixed into the
same SPPKG.

## Local development setup

From the sample root:

```powershell
npm install
npm run start
```

Load the SharePoint or Copilot Workbench with:

```text
?debugManifestsFile=https%3A%2F%2Flocalhost%3A4321%2Ftemp%2Fbuild%2Fmanifests.js&debug=true&noredir=true
```

Create production artifacts with:

```powershell
npm run build
.\teams-app\package-app.ps1
.\teams-app\package-app.ps1 -Check
```

The Teams packaging script regenerates and verifies the aligned Copilot, web-part, and Teams artwork in
addition to the isolated Teams ZIP.

## Demo flow

### 1. Introduce the two patterns

**Say**

> Personal Links is deliberately small as a business scenario. The interesting part is the engineering
> pattern: the same component experience appears in SharePoint, Copilot, and Teams, while one
> least-privilege App Folder file follows the signed-in user across those surfaces and devices.

**Show**

- The segmented blue, green, magenta, and coral accent in the UX.
- The matching interlocking-link icon in the SharePoint toolbox or Copilot agent.
- The compact Personal Links web part on a SharePoint page.

**Key point**

The hosts do not contain separate implementations. They adapt one shared application.

### 2. Demonstrate the Compact experience

**Action**

1. Open the SharePoint web part or invoke Personal Links in Copilot.
2. Point out the icon-forward links and OneDrive status.
3. Open an existing link.
4. If more than one page exists, use Previous and Next to reach every saved link.
5. Select **Open OneDrive App Folder** and show `personal-links-v1.json` in the current user's actual
   application folder.
6. Select the plus button.

**Call out**

- Compact mode prioritizes viewing and opening links.
- Copilot uses the shared six-link page size; it has no author property pane.
- SharePoint authors can configure 3, 6, 9, or 12 links per Compact page.
- The App Folder action uses the `webUrl` returned by Graph; it does not guess the tenant or user path.
- Copilot requests a larger inline iframe before showing the editor.
- The Fluent dialog and root-height behavior keep the complete editor visible.
- Closing or saving returns the Copilot component to its compact size.

Suggested Copilot prompts:

- `Show my personal links.`
- `Help me add a personal link.`
- `Help me find a link I saved.`

### 3. Create a link

**Action**

1. Enter a title and an absolute HTTP or HTTPS URL.
2. Add an optional description.
3. Choose a Fluent icon.
4. Save.

**Call out**

- The same editor is reused in Compact and Full modes.
- Validation rejects empty titles and unsafe/non-HTTP URL schemes.
- The selected icon is stored as a stable key rather than serialized React or SVG content.
- A successful write updates the local list and the versioned App Folder document.

### 4. Continue to Full mode

**Action**

1. In Copilot, select **View in full screen**.
2. Alternatively, show a web part configured as **Full** or the SharePoint full-page app.
3. Search for a link.
4. Select a card and edit it in the inspector.
5. Move a link up or down.
6. Demonstrate confirmed deletion if the seeded content can be safely removed.

**Call out**

- Full mode shows the complete collection and always-available editor on wider screens.
- Search covers title, hostname, and description.
- Ordering uses accessible Move up and Move down actions rather than drag-and-drop-only interaction.
- Create, edit, delete, ordering, validation, and error states remain shared across every host.

### 5. Prove cross-host and cross-device state

**Action**

1. Save a clearly recognizable change in Copilot.
2. Select **Open App Folder** in Full mode and show the versioned JSON file at the folder level.
3. Return to SharePoint and reload the component or use **Retry**.
4. Show the same change in the web part or full-page app.
5. If available, open the Teams personal app and show the same collection in Full mode.
6. Optionally repeat from another browser or device signed in as the same user.

**Say**

> There is no host-specific settings store. Every host reads the same
> `personal-links-v1.json` file from this user's OneDrive App Folder.

**Call out**

- State is per user, not tenant-wide.
- App Folder storage is available across devices through Microsoft Graph.
- Cross-host consistency occurs on load or explicit retry; this sample does not implement live push.
- Teams removes the in-app product bar because Teams already supplies app and user chrome.

### 6. Show graceful setup failures

Use a tenant or account without the permission approval only when it is safe to do so.

**Expected behavior**

- HTTP 401 or 403 shows the required `Files.ReadWrite.AppFolder` approval and directs the user to
  **SharePoint admin center > Advanced > API access**.
- A missing App Folder root explains that OneDrive must be provisioned or opened once.
- A missing `personal-links-v1.json` is treated as a valid first run, not an error.
- Invalid or unsupported future documents are not silently overwritten.
- Save conflicts produce an explicit refresh/retry path.

### 7. Demonstrate temporary demo mode

**Action**

1. Edit the SharePoint web part.
2. Set **Links per Compact page** to 3 and show the seeded links across two pages.
3. Explain that this web-part authoring option is unavailable to Copilot and unnecessary in Teams Full
   mode.
4. Enable **Use temporary demo data**.
5. Create, edit, reorder, and delete sample links.
6. Refresh the page to show that the seeded collection returns.

**Call out**

- Demo mode is SharePoint-web-part-only and never calls Microsoft Graph.
- Copilot and Teams do not expose a storage selector and always use the signed-in user's OneDrive App
  Folder through `GraphPersonalLinksService`.
- The disclosure remains visible so temporary actions are not mistaken for persistence.
- It enables UX demonstrations before API permission approval without introducing a second permanent
  storage mechanism.

## Technical walkthrough

### Shared host architecture

Start with the two thin adapters:

- `src/copilotComponents/personalLinks/PersonalLinksCopilotComponent.tsx`
  - selects Compact or Full from the Copilot display mode;
  - requests inline editor resizing and full-screen mode;
  - opens links through the Copilot bridge; and
  - publishes bounded model context.
- `src/webparts/personalLinks/PersonalLinksWebPart.ts`
  - selects Auto, Compact, or Full;
  - chooses Graph or in-memory demo storage;
  - applies SharePoint theme changes;
  - forces Full mode in Teams; and
  - suppresses duplicate product chrome in Teams.

Both adapters render:

- `src/shared/components/PersonalLinksApp.tsx`
  - Compact and Full layouts;
  - CRUD, search, ordering, dialogs, icon picker, messages, and permission UX.
- `src/shared/components/PersonalLinksThemeProvider.tsx`
  - Fluent light/dark theme and owner-document Griffel rendering.
- `src/shared/components/PersonalLinksErrorBoundary.tsx`
  - accessible recovery when an unexpected rendering error occurs.

### App Folder persistence

Walk through:

- `src/shared/services/IPersonalLinksService.ts`
  - host-independent storage contract and typed error categories.
- `src/shared/services/GraphPersonalLinksService.ts`
  - `/me/drive/special/approot` access;
  - current-user App Folder `webUrl` resolution for the demo action;
  - `personal-links-v1.json` read/write;
  - first-run file handling;
  - eTag and `If-Match` concurrency protection; and
  - permission, provisioning, conflict, schema, and network error mapping.
- `src/shared/services/MemoryPersonalLinksService.ts`
  - seeded, non-persistent implementation used only by web-part demo mode.
- `src/shared/models/personalLinks.ts`
  - versioned document schema, URL validation, parsing, icon keys, and normalized ordering.

The permission is declared in `config/package-solution.json`:

```json
{
  "resource": "Microsoft Graph",
  "scope": "Files.ReadWrite.AppFolder"
}
```

### Copilot routing and model context

Show:

- `src/copilotComponents/personalLinks/PersonalLinksCopilotComponent.manifest.json`
  - optimized positive intent and explicit negative routing boundaries.
- `copilot/instruction.txt`
  - instructs the agent to use the interactive component and avoid inventing link details.
- `copilot/ai-plugin.json`
  - model-facing action description.
- `copilot/declarativeAgent.json`
  - agent description and conversation starters.

The model context intentionally publishes a bounded summary and visible item metadata. It excludes URLs,
descriptions, hidden records, and unsaved drafts.

### Branding and packaging

Show:

- `src/webparts/personalLinks/PersonalLinksWebPart.manifest.json`
  - embedded custom web-part toolbox image.
- `copilot/color.png` and `copilot/outline.png`
  - Copilot agent artwork.
- `teams-app/package-app.ps1`
  - deterministic generation and validation of all icon sizes and the manual Teams ZIP.
- `teams-app/personalLinks/manifest.json`
  - personal-only Teams routing through `TeamsLogon.aspx` and `teamshostedapp.aspx`.

Explain why `teams-app` is separate:

- SPFx treats the top-level `teams` directory as reserved package input.
- The Copilot build already writes `teams/personal-links.zip`.
- Keeping the manual Teams app in `teams-app` prevents `TeamsSPFxApp.zip` from being copied into the
  same SPPKG as the Copilot package.

## Validation and reset

Before publishing or recording the demo:

```powershell
npm run build
.\teams-app\package-app.ps1 -Check
git diff --check
```

Expected results:

- TypeScript and ESLint pass.
- All model and storage tests pass.
- The SPPKG contains one `ClientSideAssets/personal-links.zip`.
- The SPPKG contains zero `TeamsSPFxApp.zip` entries.
- The isolated Teams ZIP contains exactly `manifest.json`, `color.png`, and `outline.png`.

To reset production data, delete `personal-links-v1.json` from the application's OneDrive App Folder.
To reset demo data, reload the page or create a new web-part instance.

## Closing message

> The scenario is intentionally simple, but the pattern is reusable: keep host adapters thin, centralize
> the React experience and storage contract, request the smallest Graph permission that fits, and package
> Copilot and Teams artifacts independently when the current toolchain cannot combine them safely.
